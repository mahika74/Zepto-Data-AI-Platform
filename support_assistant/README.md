# Module 3 - Zepto Support Assistant

## Overview

This module implements a retrieval-augmented support assistant for answering Zepto-related customer policy questions.

The system combines:

- Local document knowledge
- Sentence-transformer embeddings
- ChromaDB vector search
- LangGraph workflow orchestration
- Structured prompting
- Deterministic mock LLM behavior
- Pydantic response validation
- FastAPI
- Docker

The complete workflow is:

**Policy Documents → Embeddings → ChromaDB → Intent Classification → Retrieval → Answer Generation → Structured API Response**

---

## Knowledge Base

The assistant uses eight policy documents stored in the `docs/` directory.

```text
docs/
├── doc_01.txt
├── doc_02.txt
├── doc_03.txt
├── doc_04.txt
├── doc_05.txt
├── doc_06.txt
├── doc_07.txt
└── doc_08.txt
```

These documents provide the policy information used by the assistant when answering supported Zepto-related questions.

The assistant is designed to answer policy questions using the retrieved document context rather than relying on unsupported information.

---

## Document Embeddings and Retrieval

The knowledge base is converted into vector representations using the local:

`all-MiniLM-L6-v2`

sentence-transformer model.

The embeddings are stored in **ChromaDB** for semantic similarity search.

The retrieval workflow is:

```text
Policy Documents
       ↓
Text Embedding
       ↓
ChromaDB
       ↓
Semantic Similarity Search
       ↓
Relevant Policy Context
```

The embedding model runs locally, so the system does not require a paid embedding API.

---

## Structured Prompting

The support assistant uses a structured prompt containing:

- Role
- Context
- Task
- Output format
- Length constraint
- Negative constraint
- Few-shot example

The prompt is designed to keep responses focused on the retrieved policy information and restrict unsupported answers.

---

## LangGraph Workflow

LangGraph is used to orchestrate the support assistant workflow.

The graph contains three main processing nodes:

- `classify_intent`
- `retrieve_and_answer`
- `direct_answer`

The workflow uses conditional routing based on the detected intent.

```text
                    START
                      |
                      v
              classify_intent
                 /         \
                /           \
      Policy Question     General Question
            |                   |
            v                   v
 retrieve_and_answer       direct_answer
            |                   |
            \___________________/
                      |
                      v
                     END
```

### `classify_intent`

Determines whether the user's query is related to the supported Zepto policy knowledge base.

### `retrieve_and_answer`

For policy-related questions, the system retrieves relevant documents from ChromaDB and generates an answer using the retrieved context.

### `direct_answer`

For unsupported or general questions, the assistant provides a controlled response instead of retrieving unrelated policy information.

---

## Deterministic Mock LLM

The project uses a deterministic `MOCK_LLM` behavior by default.

This allows the complete application to run without requiring a paid external language-model API.

The mock behavior is useful for:

- Local testing
- Reproducibility
- Docker testing
- CI/CD verification
- Demonstrating the complete retrieval and API workflow

## Response Schema

The assistant uses Pydantic to validate the API response.

The response contains:

```json
{
  "answer": "...",
  "sources": [],
  "confidence": 1.0
}
```

### Fields

- `answer` — Final response generated by the assistant
- `sources` — Documents used to support the response
- `confidence` — Confidence value associated with the response

## FastAPI

The support assistant is exposed through a FastAPI application.

### Endpoint

```text
POST /ask
```

The endpoint accepts a user question and returns a structured response.

### Example Request

```json
{
  "query": "What is the delivery fee?"
}
```

### Example Response

```json
{
  "answer": "Based on the retrieved context: ...",
  "sources": [
    "doc_01.txt"
  ],
  "confidence": 1.0
}
```

For a general question outside the supported Zepto policy domain, the assistant returns a controlled response and does not provide unrelated information.

---

## Example Query Types

### Policy Question

```text
{
  "query": "What is the delivery fee?"
}
```

The system:

1. Classifies the query
2. Searches the ChromaDB knowledge base
3. Retrieves relevant policy information
4. Generates the response
5. Returns the answer with its source information

### General Question

```text
{
  "query": "What is the capital of India?"
}
```

The system recognizes that the question is outside the supported policy domain and returns a controlled response instead of searching the Zepto policy documents.

## Docker Build Process

The Docker image:

1. Installs the required dependencies
2. Downloads/loads the local embedding model
3. Copies the support assistant source code
4. Builds the ChromaDB document index
5. Starts the FastAPI application

This allows the complete support assistant to run inside a container.

## Design Decisions

- The knowledge base consists of eight local policy documents.
- A local `all-MiniLM-L6-v2` model is used for embeddings.
- ChromaDB provides semantic document retrieval.
- LangGraph separates intent classification, retrieval, and direct-answer behavior.
- The system uses a deterministic `MOCK_LLM` by default so that it can run without a paid language-model service.
- Pydantic validates the final response structure.
- FastAPI provides a simple REST API.
- Docker provides a reproducible deployment environment.
- The ChromaDB index is built during the Docker image build.
- General questions are handled separately from policy questions to prevent unrelated responses.

---

## Conclusion

Module 3 provides a complete local retrieval-based support assistant that combines document embeddings, vector retrieval, LangGraph workflow orchestration, structured responses, FastAPI, and Docker.

The implementation is designed to be reproducible without paid external services and can be tested locally or through the project's automated Docker workflow.
